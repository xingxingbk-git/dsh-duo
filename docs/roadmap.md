# 开发路线

状态：2026-10-09 更新。账号授权门槛和退出行为已确认；当前源码仍为空骨架，尚无可运行的模式切换或真实聊天。

## 阶段 0：文档与项目骨架（已完成，未构建验收）

- 已建立 Host/Client 双入口、bundle patch、manifest 和构建脚本草案。
- 已更新需求和验收矩阵：未登录/未授权整个控件置灰；启动 pending 默认为 HARNESS；CHAT 中退出/官方确认授权失效立即返回 HARNESS 并禁用；重新授权不自动切 CHAT；同账号持续有效的授权刷新保持用户当前模式。
- 已读取官方文档正文及固定源码 `639ed015397290b3745d163aafe02ffee4aa3f84`，目标安装元数据为 DSH `0.2.0-rc.2`、Cordis `4.0.4`、React `18.3.1`。
- 创建阶段 Inspect 摘要属于旧记录，本轮无 live Inspect；尚未安装依赖、完整编译、安装插件或运行 UI。
- 已建立全项目上下文机制：AGENTS 入口/协议、handoff 当前任务总表/分工、worklog 决策与工作历史。此机制贯穿所有阶段，包含分析/调研/失败/任务目标，不限于登录逻辑；每阶段成果与上下文同步提交。

## 阶段 1：官方授权与扩展能力发现（下一步前置）

- 连接目标 DSH，先 Cordis Inspect `list`，再使用准确 Provider/Method 核对；记录当前版本、来源和调用契约。
- 首先确认 DeepSeek 账号授权状态的官方读取/持续观察能力、账号标识，以及退出/授权失效/撤销通知。不能以网络错误判定登出，不猜服务方法或事件名。
- 定义授权适配器及可测试状态输入：启动 pending → HARNESS 禁用；首次授权/重新登录有效 → 启用且保持 HARNESS；同账号持续有效的刷新/通知 → 保持当前用户选定模式；确认失效/换账号 → 即时退出 CHAT 并禁用。
- 复查品牌区域 `aria-hidden`、外层 New Session 点击与折叠不可达问题；找到官方可交互入口后才能实施切换控件。
- 复查 `sidebar.workspaces`、main panel、layout 和原新建/快捷键契约。优先验证自有 main panel 的原生右栏隐藏行为，确认原 `activePanelId` 的读取/恢复方式。
- 网页历史同步作为独立能力记录；账号授权门槛不证明历史开放。
- **阶段验收**：授权观察和关键 UI 契约有准确官方证据；未确认项保持待验证，不能对用户开放或声称已支持 CHAT。

## 阶段 2：构建与受授权门槛控制的 UI spike

- 按目标版本对齐 peer/dev 依赖，生成锁文件，保持单份 Cordis/React；补齐 TSX 类型检查和实际需要的样式/资源构建。
- 核对 lazy-CJS 产物、共享基线、`dsh.client.inject` 与精确 `dsh.client.external`，避免未知 require 或重复运行时实例。
- 在独立开发 profile 执行安装、dump-config、启动；验证 `pnpm typecheck`、`pnpm build` 与禁用/卸载恢复，记录完整复现步骤。
- 实现可达的 `CHAT | HARNESS` 控件。所有进入 CHAT 的入口统一受授权门槛控制，整个控件禁用，不能只禁用 CHAT 标签。
- 用 mock Chat main panel 验证双向切换；CHAT 才占用聊天侧栏 Slot，离开时 dispose 恢复内置 occupant。处理 workspace 区外原 New Session、品牌点击及快捷键，防止 CHAT 操作误触 Harness session。
- 进入前保存原 `activePanelId`，退出时恢复该值；验证原生布局隐藏右栏且其 open/closed、tab、width、fullscreen 均不改变。
- 按需求验收矩阵覆盖启动 pending、未授权、首次授权、同账号有效刷新、退出、撤销、网络错误、重新授权、账号切换、生成中切换、键盘/屏幕阅读器、窄窗口/折叠和卸载。
- **阶段验收**：门槛和可逆布局通过 UI 测试，官方授权输入通过适配验证；mock 不证明真实发送、流式取消或网页历史同步。

## 阶段 3：授权后的真实聊天

- 先确认第三方插件可用的官方模型、会话/发送、流式返回与取消能力，再接入 conversation provider；不开放匿名或绕过账号授权的本地/API 模式。
- 所有发送入口在发送前检查当前账号及授权；退出/确认失效立即禁止新发送并回 HARNESS，不等待取消或保存确认。
- 按官方取消能力结束旧账号活动流式请求，防止晚到回调串入新账号；保留已接收内容与草稿，按账号隔离。
- 确定并实现数据落盘、保留期限、同账号恢复、导出/删除与缓存说明；未确定前不承诺具体持久化行为。
- 实测有效授权及同账号刷新、登出/撤销、网络故障、重新授权、账号切换和流式取消；没有官方取消证据时，不标记真实聊天退出验收通过。
- **阶段验收**：真实聊天、授权观察、退出恢复与数据隔离有可复现实测；数据来源、权限和限制清楚标注。

## 阶段 4：网页账号历史同步评估（独立里程碑）

- 只有官方明确支持第三方授权与网页历史接口，才进入开发；前述授权和聊天阶段通过不自动启动本阶段。
- 核实历史读写范围、撤销、账号隔离、缓存和用户告知；不采集密码/Cookie/令牌，不模拟网页登录，不依赖私有 Web API。
- 没有官方支持时明确标注网页历史同步不可用，不把插件自己的数据冒称网页历史。
- 本插件不提供匿名聊天，不做匿名转账号或跨账号自动合并；其他来源历史的迁移需独立官方能力和用户决策。
- **阶段验收**：官方来源、真实授权流程与历史同步测试全部成立后才声明支持。

## 阶段 5：发布准备

- 测试目标 DSH 版本的安装/更新/回滚、禁用/卸载恢复、授权变化、账号隔离、无障碍和隐私。
- 选择预构建 npm/tarball 或完整 Git 安装构建方案，说明安装及必要的构建许可。
- 发布 README、变更日志、权限、数据流、存储策略、兼容版本和限制；所有未验证能力仍标记待验证。

各阶段必须记录日期、目标版本、固定官方来源、复现步骤、产物/界面证据与 mock/真实运行边界。先完成一个可验证阶段，再推进下一阶段。
