# dsh-chat 需求规格：CHAT / HARNESS 模式切换

状态：2026-10-10更新；W016候选版0.1.2使用真实官网聊天和服务器历史，共用DSH原生侧栏镜像官网导航，按用户授权做有限侧栏适配。网页登录状态联动、菜单/快捷键新建语义及真实两端一致性仍未完整实现/验收；当前分层验证见handoff。

## 本轮用户澄清与试用范围

- 2026-10-10侧栏截图修订：CHAT与HARNESS共用原DSH侧栏外壳，窗口按钮/品牌/折叠位置、新会话视觉、背景颜色/透明度/模糊度、底部真实账号入口保持一致，只按模式调整必要区域。CHAT列表使用官网真实标题、置顶/昨天/日期分组，不提供项目/项目内新建；不能用说明面板或假列表代替。W016顶部新会话经用户批准的有限适配转交官网；菜单/快捷键仍走HARNESS，不能将鼠标/Enter验证写成全部路径完成。
- 用户需要 `chat.deepseek.com` 同一账号的真实聊天与历史，在插件中产出的对话仍由网站存储并在网页可见。DSH 模型调用加插件本地记录不满足需求，不作为替代产品实现；不询问插件本地聊天保存策略。
- 首选DSH原生框架呈现网页Chat内容；用户允许内嵌真实网页，并进一步允许有限界面适配将已加载官网列表镜像进原生左侧，成功后隐藏重复网页侧栏。右侧正文/编辑器仍由官网提供，不能称为全部原生重绘或官方历史同步API。
- 用户此前接受临时入口；2026-10-10截图要求以顶部品牌入口替代底部及右下角入口。原Harness新建快捷键限制仍保留；使用原快捷键可能新建Harness session并退出CHAT，不把这一行为当成完整状态保真验收通过。
- DSH 账号授权门槛沿用已确认规则。网页登录是独立会话，不能确认网页账号与 DSH 账号相同，也不能通过公开桥观察网页内部登出；官网退出后的即时回 HARNESS 仍未实现，网页自身显示登录状态。DSH 官方确认登出/失效的回退可以实现并单独验证。
- 适配只能识别页面处于登录视图并清空列表；不将页面路径或标题当作账号授权/退出通知，不改变上述门槛规则。结构不匹配时恢复官网原导航，不能保留失效的假可点击列表。
- Desktop guest 登录存储由 DSH 原生安全分区管理，仅保留当前应用进程；不共享系统浏览器登录，重启需重新网页登录。已发送并由网站保存的服务器历史由网站恢复，未发送草稿/网页流在卸载或授权代次变化销毁容器时无法由插件提取保留。
- 手动CHAT/HARNESS切换保留同一网页容器，只隐藏它；不读取密码/Cookie/令牌，不调用私有网页接口，不改变安装包或网页安全策略。官网DOM仅用于用户批准的导航镜像/操作/隐藏，内存使用、不读取正文/站点存储/私有应用状态；DSH DOM仅允许AGENTS中的三个侧栏适配行为，其余仍禁止。

## 1. 背景与目标

在 DSH 中提供两种可切换的工作体验：

- **HARNESS**：当前 DSH 编码/Agent 工作区，保持现有功能和布局。
- **CHAT**：接近 DeepSeek 网页聊天的对话体验，复用 DSH 主框架，使用独立的对话导航和聊天主区。

CHAT 仅对已登录且具有有效 DeepSeek 账号授权的用户开放。未登录、未授权及启动时尚未确认授权的用户，默认处于 HARNESS，整个 `CHAT | HARNESS` 切换控件置灰禁用。本插件不提供匿名聊天，也不提供绕过该门槛的本地/API 聊天入口。

有效 DSH 账号授权只决定候选版 CHAT 是否可进入。网页嵌入路线由真实网页自行显示和保存网页账号历史；插件不复制、合并或同步一份本地历史。原生历史接口与网页实际加载/登录/两端一致性仍须分别验证。

## 2. 交互与视觉需求

### 2.1 模式选择器

2026-10-10截图修订：移除品牌后的静态HARNESS徽标，将切换器移到顶部品牌区域；删除Harness侧栏底部模式/常驻刷新入口及右下角浮动模式框。正常授权时不展示刷新提示，失败时在顶部提示并重试。折叠后通过原展开控件回到顶部入口，不添加新的角落入口；插件禁用恢复原品牌徽标。

- 顶部左侧保留 DeepSeek 图标，以 `CHAT | HARNESS` 两段式切换器取代图标右侧的 `HARNESS` 品牌字样。
- 活跃项使用接近当前 HARNESS 标识的白底选中态；未授权时保留 HARNESS 当前状态，同时将整个控件置灰，鼠标、键盘和快捷入口均不能切入 CHAT。
- 启动授权检查完成前，显示 HARNESS 和禁用控件；不得先恢复上次 CHAT 再等待鉴权。
- 授权调用/协议挂载失败必须显示可理解的故障和可访问的刷新入口；单次检查超过35秒结束等待，初始未确认状态变为不可用，仍保持HARNESS禁用。重试成功保持HARNESS，不自动进入CHAT；超时的迟到回包不能重新开启门槛。
- 首次确认有效授权或重新登录/授权后启用控件，保持 HARNESS；用户手动选择 CHAT 后才进入聊天模式。同一账号授权持续有效的刷新/订阅通知保持用户当前选定的 CHAT/HARNESS，不重置模式。
- 控件提供清晰焦点态、正确的 selected/pressed 与 disabled 语义，并说明“登录并授权 DeepSeek 账号后可使用 CHAT”。支持键盘、屏幕阅读器、窄窗口与折叠侧栏。
- 品牌名Slot只放非交互字标和自有锚点；实际按钮通过官方shell.overlay对齐品牌位置，避开 `aria-hidden` 与外层New Session。折叠/遮蔽时隐藏交互层，展开恢复；macOS实测与其他平台未验证状态分别记录。
- 普通手动切换必须可逆，不静默丢失 Harness 状态、聊天草稿或已接收回答。强制退出 CHAT 的授权失效流程见第 3 节。

### 2.2 CHAT 模式

- W017截图修订：登录/刷新后在首次可见帧即完成官网布局适配，不先闪现原网页侧栏；隐藏重复导航时同时撤销其布局占位及紧凑网页导航头部，主内容使用全部可用宽度。结构不支持时明确恢复官网原界面。
- 删除整个插件主区顶部工具栏（官网标题/域名/备用模式选择等）；折叠时只保留与HARNESS一致的原生风格窗口展开/新建控件。
- DSH设置中提供独立“CHAT设置”：显示官网当前可见的真实账号资料，操作网页公开设置UI的系统语言等选项，官网实际值为准；CHAT固定暗色，不提供外观选择（W017用户补充）。未登录/无法识别时清楚说明并可进入官网设置。不得用DSH授权身份冒充网页身份，不读取密码、Cookie、token、storage或调用私有API。


- W016新增截图验收：品牌切换器靠右，字标与控件之间自动填充剩余空间；CHAT不显示插件导航行，顶部“新会话”创建官网Chat对话；主区移除常驻“刷新网页”“官网导航”按钮及插件底部提示条。加载失败仍需可重试，折叠后仍能展开/返回HARNESS。保留原侧栏材质、窗口区和真实DSH账号入口。
- 用户希望官网与DSH登录一致；只有发现面向Chat的官方SSO/会话桥才实现，不能把Platform登录凭据迁移到官网或读写Cookie/token来伪造共用登录。
- 用户已批准W016限定DSH侧栏适配：仅品牌间距、CHAT插件行隐藏及原顶部新会话点击；使用原组件，HARNESS/禁用可逆撤回。它是用户批准的兼容适配，不是rc.2新增官方动作接口。菜单/快捷键不属于这次DSH DOM例外，继续单独标注限制。
- 沿用 DSH 主框架，左侧为新建对话、对话历史、搜索/筛选（若支持）、账号/设置入口。
- 选中历史对话后主体显示该对话；新建对话显示空状态与输入区。仅替换 `sidebar.workspaces` 不足以完成 CHAT：原 New Session、品牌区点击、相关快捷键以及其他 Harness 导航入口必须通过官方扩展点处理，避免在 CHAT 内意外创建或切换 Harness session。
- 默认隐藏 Harness 专属右侧面板，聊天内容使用可用主宽度。优先采用自有 main panel 的原生布局行为，不将用户的右栏开闭状态当成 CHAT 状态保存。
- 明确加载、空历史、网络/服务错误、停止生成、重试、删除/归档（若支持）等状态。
- Chat 与 Harness 的会话、文件、工具及草稿状态彼此隔离；不同 DeepSeek 账号的 Chat 数据彼此隔离。
- 所有新发送入口受同一授权门槛约束。模型和会话数据来源必须由已确认的官方能力支持，不因控件启用就展示未验证的网页历史。

### 2.3 HARNESS 模式与恢复

- 恢复 DSH 原侧栏、主工作区与既有交互，保留当前 Harness session。
- 进入 CHAT 前记录原 `activePanelId`；退出时恢复该值，包括原先为 `null` 的情况，不一律跳回 Conversation。
- 使用原生 main panel 隐藏右栏时，返回 HARNESS 后应保留原 rightbar 开闭、tab、width 与 fullscreen 状态。确需显式调整右栏时，必须先确认官方读取与恢复契约。
- 插件禁用/卸载后恢复原界面和导航，不残留 Chat panel、替代侧栏、快捷键或面板隐藏状态。

## 3. 登录、授权与数据策略

以下为已确认的产品行为；DSH 的公开安全状态/资料/观察契约已静态确认并接入；网页自身没有公开身份/退出通知。不允许猜测 API 名称或以网络错误代替退出信号。

| 情况 | 模式与切换控件 | 数据/发送行为 |
|---|---|---|
| 启动时授权待确认（pending）或授权能力不可用 | 默认 HARNESS，整个控件置灰禁用 | 不恢复 CHAT，不开放匿名聊天；等待官方状态确认 |
| 未登录或未授权 DeepSeek 账号 | HARNESS，整个控件置灰禁用 | 不开放 Chat 新建、发送或任何绕过门槛的入口 |
| 首次确认当前账号授权有效 | 保持 HARNESS，启用控件；用户可手动进入 CHAT | 仅接入已经验证的数据源；授权有效不代表网页历史可同步 |
| 同一账号授权持续有效的刷新/订阅通知 | 保持用户当前选定的 CHAT/HARNESS，控件继续启用 | 不因重复有效通知退出 CHAT，也不重置对话/草稿 |
| CHAT 中 DSH 官方确认退出登录或授权失效/撤销 | 立即自动回 HARNESS，再禁用整个控件；不等待用户确认 | 隐藏并释放旧网页容器，禁止继续通过插件使用；官网已保存内容由官网管理，网页草稿与在途生成受公开能力限制 |
| 官网网页内部退出登录 | 可识别官网登录视图，但没有官方身份/退出通知桥；不自动回HARNESS | 官网控制自己的聊天授权，禁用官网新建；登录视图不能证明DSH授权失效或两处账号相同 |
| HARNESS 中退出登录或官方确认授权失效 | 保持 HARNESS，禁用整个控件 | 同样阻止 Chat 新发送，并清理该账号的活动请求 |
| 网络超时、断网、服务错误 | 不将错误自行判定为登出/授权撤销；授权门槛遵循官方已确认状态 | 展示网络/服务错误；启动仍未确认授权时继续 HARNESS 禁用；发送可因网络不可用而暂停 |
| 再次登录/授权成功 | 保持 HARNESS，重新启用控件 | 不自动进入 CHAT；仅在用户选择后展示当前账号自己的数据 |
| DSH 账号切换 | 结束旧账号 CHAT，回 HARNESS；新账号授权确认前控件禁用 | 释放旧容器，以新的 DSH 账号隔离分区创建网页；网页实际身份由网站登录决定，新账号确认授权后也不自动进入 CHAT |

强制退出 CHAT 时，界面恢复和禁用控件不得等待流式取消完成或弹出保存确认。候选版没有自己的模型请求或聊天存储：已发送内容的保存、恢复、导出和删除遵循官网行为，不再提出插件本地记录策略。插件隔离旧容器和迟到 lease 回包，但没有公开网页流式取消或草稿提取能力；销毁容器时网页草稿可能丢失，不能把这一限制写成已实现的保留能力。完整最终要求仍列在第 5 节，未满足项须保留状态标记。

**安全底线**：不采集密码，不读取浏览器 Cookie，不自行读取/持久化访问令牌，不模拟网页登录或调用未公开 Web API。账号秘密只由官方授权/凭据机制托管。账号历史同步必须另有官方支持的授权与接口证据。

## 4. 范围与非目标

本轮范围：固定 Desktop 0.2.0-rc.2 的官方授权与 Browser lease 契约，实现受 DSH 授权门槛控制的真实网页容器与可逆 DSH 导航；分别执行纯状态测试、mock 容器生命周期验证和真实 Desktop 人工验收。没有真实网页登录/发送/另一浏览器历史一致性证据前，不声明这些已通过。

非目标：匿名聊天、匿名转账号自动迁移、绕过 DeepSeek 账号授权的本地/API 聊天、替换 DSH Agent 能力、抓取网页版接口、复制未确认开放的网页源码、保证与网页端逐像素一致。

## 5. 验收矩阵

下表保留完整最终体验要求。W015导航镜像已有实测；W016顶部click转交已实现，但已登录官网新建、菜单/快捷键保真与官网内部退出联动等仍未完整验收/实现，不能以模拟或构建替代。具体分层证据见handoff。

| 测试情景 | 必须满足的结果 |
|---|---|
| 启动 pending，包括此前曾选择 CHAT | HARNESS 首次渲染；整个控件 disabled；没有闪现 CHAT 或发送窗口 |
| 未登录/未授权 | 整个控件置灰；点击、键盘、快捷入口均不能进入 CHAT |
| 登录/授权成功 | 控件启用，仍为 HARNESS；手动选择才进入 CHAT |
| 同一账号持续有效的授权刷新/订阅通知 | 保持当前 CHAT/HARNESS；已进入 CHAT 时不被切回，不重置当前对话/草稿 |
| CHAT 手动返回 HARNESS，再进入 CHAT | 恢复原 `activePanelId` 和 Harness session；Chat 已接收内容/草稿仍在 |
| 原右栏关闭、打开、不同 tab/width/fullscreen | CHAT 不显示右栏；返回后各项与进入前一致 |
| CHAT 中官方确认登出/授权失效 | 不弹确认、立即回 HARNESS 并禁用整个控件；所有新发送立即被阻止 |
| 流式生成中退出/授权失效 | 界面即时退出；按官方能力取消旧请求；已接收内容/草稿保留；晚到回调不写入其他账号 |
| 断网/超时/服务错误 | 显示真实错误，不伪装为已登出；未确认授权的启动仍保持禁用 |
| 初始授权调用、协议挂载失败或超过35秒 | 不无限pending，显示失败/超时及可访问重试；成功恢复后仍HARNESS；忽略超时迟到回包 |
| 重新授权或切换账号 | 仍从 HARNESS 开始；账号隔离；不自动跳 CHAT 或合并历史 |
| CHAT 内新建、品牌点击、相关快捷键 | 只执行已定义的 Chat 行为，不意外新建/切换 Harness session |
| 顶部品牌入口与清理 | 原静态HARNESS徽标消失；白底选中切换器在品牌后；Harness底部与右下角无旧控件；正常无常驻刷新，失败可重试；禁用恢复原品牌 |
| 键盘、屏幕阅读器、窄窗口、折叠侧栏 | 选择器可达、语义正确；无 `aria-hidden` 遮蔽或外层New Session误触；折叠隐藏顶部入口，展开恢复 |
| 禁用/卸载插件 | 原侧栏、面板、快捷键和 Harness 原行为恢复，无残留 |
| 安装交付 | 预构建 tarball 和声明支持的 Git 源码安装分别验证；Git 构建获准后两个 lib 入口存在且 Host 可导入，不能仅用 tarball 成功证明仓库地址可安装 |
| 真实聊天/网页历史能力声明 | 各自具备官方来源、目标版本、授权流程和可复现实测证据；未验证项清楚标注不可用 |

mock 能验证模式状态与退出流程，但不能证明真实授权、流式取消或账号历史同步已实现。

## 6. 待技术核实与数据决策

- DSH 安全账号状态/资料/watch 与登出契约已有固定官方依据，真实联动待验收；官网内部账号/退出通知无公开桥。
- 真正网页登录、验证码、发送、网页流与两端历史一致性；不接独立模型对话代替官网。
- 官网自己负责已发送内容和历史；插件仅镜像导航元数据，不提取/保存正文。授权变化或卸载销毁网页时的未发送草稿、在途生成仍受公开能力限制。
